4. I want to create a  user "book" to run the deployed system on the production machine. What priviliges do the user book need to allow start with systemd

1. Skapa användaren book

Skapa en systemanvändare med hemkatalog (t.ex. /usr/local/book):

bash
# Skapa systemanvändaren 'book'
sudo useradd -r -m -d /usr/local/book -s /bin/bash book

(Om du inte vill att någon ska kunna logga in interaktivt som book kan du använda -s /usr/sbin/nologin istället).

2. Rättigheter i filsystemet

Användaren book behöver:

A. Ägandeskap över deploy-katalogen och databasen
bash
sudo chown -R book:book /usr/local/book
B. Rättigheter för SQLite (Viktigt!)

SQLite kräver skrivrättigheter både på själva .db-filen och på katalogen där databasen ligger (eftersom SQLite skapar temporära journal-/WAL- och låsfiler vid skrivningar):

bash
# Ge skrivrättigheter på databasfilen och dess katalog
chmod 750 /usr/local/book
chmod 600 /usr/local/book/booking_system.db
C. Konfigurationsfilen (application.properties)
bash
chmod 600 /usr/local/book/application.properties
D. Exekveringsrättighet för Java och Node

Normalt har alla användare redan läs- och körrättighet (755) på:

/usr/bin/java
/usr/bin/node och /usr/bin/npx
3. Nätverksportar (Inga särskilda rättigheter krävs)
Tjänsterna använder port 9091 (backend) och 3001 (frontend).
I Linux kan vanliga oprivilegierade användare fritt binda till alla portar över 1024. Det behövs alltså inga särskilda nätverks-capabilities (som CAP_NET_BIND_SERVICE).
4. Service-filerna i systemd

I både bookingweb.service och bookingapp.service sätter du:

ini
[Service]
User=book
Group=book
WorkingDirectory=/usr/local/book/deploy/bookingweb   # resp. bookingapp
5. Om du vill att book ska kunna starta/stoppa tjänsterna själv

Om en administratör eller ett deployment-skript inloggat som book ska kunna köra systemctl restart ... utan att ange root-lösenord, kan du lägga till en fil i /etc/sudoers.d/:

bash
sudo visudo -f /etc/sudoers.d/book-service

Lägg till raden:

text
book ALL=(ALL) NOPASSWD: /bin/systemctl start bookingweb, /bin/systemctl stop bookingweb, /bin/systemctl restart bookingweb, /bin/systemctl status bookingweb, /bin/systemctl start bookingapp, /bin/systemctl stop bookingapp, /bin/systemctl restart bookingapp, /bin/systemctl status bookingapp

Då kan book köra:

bash
sudo systemctl restart bookingweb

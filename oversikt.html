1. Systemöversikt & Arkitektur

Community Booking System är ett webbaserat bokningssystem för gemensamma resurser och lokaler (t.ex. mötesrum, verktyg, maskiner och idrottsytor). Systemet ger användare en snabb, visuell och intuitiv överblick över lediga och bokade tider i realtid via en interaktiv kalender.

Systemet är byggt enligt en modern klient-server-arkitektur:

  • Frontend SPA: En snabb Single Page Application i React och TypeScript som kommunicerar via ett REST API.
  • Backend API: En robust Spring Boot-applikation i Java som sköter affärslogik, behörigheter och databastransaktioner.
  • Databas: En lokal och fristående SQLite-databas som körs utan krav på externa databasservrar.
  • Driftmiljö: Standardiserade Linux Systemd-tjänster för automatisk omstart, felloggning och övervakning.
Kärnvärden:
  • Enkelhet för användaren genom ett guidat steg-för-steg-flöde.
  • Strikt validering mot dubbelbokningar, överlappningar och retroaktiva ändringar i dåtid.
  • Minimalt underhåll och hög portabilitet med samlad driftsättning via deploy.sh.

3. Kärnfunktioner & Användarflöde

3.1 Bokningsflödet i 5 steg

  1. Steg 1 – Välj plats (Location): Användaren väljer anläggning, fastighet eller geografiskt område.
  2. Steg 2 – Välj resurs (Asset): Val av specifik resurs knuten till platsen (t.ex. "Bana 1", "Stora konferensrummet").
  3. Steg 3 – Välj tid i kalendern:
    • Gröna block (Free): Öppettider och tillgängliga tider.
    • Röda block (Booked): Redan uppbokade tider med visning av bokarens alias.
    • Användaren klickar på ett grönt block (eller markerar ett intervall). Standard är 2 timmars bokning eller blockets kvarvarande tid.
  4. Steg 4 – Bekräfta bokning: Översikt av datum, resurs och tid. Om användaren inte är inloggad öppnas inloggningsdialogen smidigt.
  5. Steg 5 – Klart & Kvitto: Bokningsbekräftelse med bokningsnummer, plats och tider.

3.2 Avbokning och borttagning av bokad tid

  • Användaren klickar direkt på sitt röda bokningsblock i kalendern.
  • Ett bekräftelsefönster öppnas som visar detaljer (resurs, datum, tid och alias).
  • Vid bekräftelse raderas bokningen och kalendern uppdateras omedelbart med en grön bekräftelse-banner.
Säkerhets- och valideringsregler:
  • Spärr mot dåtid: Försök att boka eller avboka en tid vars starttid har passerats blockeras omedelbart med felmeddelandet: "Ändring före aktuell tid är inte tillåten". Bekräftelsefönstret öppnas inte.
  • Behörighet vid avbokning: Endast den användare som skapade bokningen, eller en användare med administratörsroll (BOOKADMIN), har rätt att ta bort bokningen.
  • Överlappningsskydd: Bokningar kan inte krocka med varandra eller sträcka sig utanför definierade öppettider.

3.3 Administratörsfunktioner (BOOKADMIN)

  • Användaradministration: Lista alla konton, skapa nya användare, tilldela roller (BOOKUSER eller BOOKADMIN) samt byta lösenord.
  • Resurs- och platshantering: Skapa, redigera och underhålla platser och tillhörande resurser.
  • Schemaläggning & Öppettider: Skapa lediga tidsintervall (Free) och köra automatisk generering av öppettider för ett helt år.

5. Drift, Uppstart & Systemd-tjänster

5.1 Tjänster och drift med Systemd

Systemet är utformat för produktion på Linux (t.ex. Ubuntu/Debian) och körs under den dedikerade systemanvändaren book via Systemd: 

# Kontrollera status på tjänsterna
sudo systemctl status bookingweb
sudo systemctl status bookingapp

# Starta, stoppa eller starta om
sudo systemctl restart bookingweb
sudo systemctl restart bookingapp

# Granska loggar via journalctl
sudo journalctl -u bookingweb -f
sudo journalctl -u bookingapp -f

5.2 Konfigurationsfil (application.properties)

Tjänsten bookingweb läser sin konfiguration från /usr/local/book/application.properties:

  • server.port=9091 – Port som Spring Boot-backend lyssnar på.
  • sqlite.db=/usr/local/book/booking_system.db – Sökväg till produktionsdatabasen.
  • jwt.secret=... – Säker hemlig nyckel för signering av tokens.
  • jwt.expiration=86400000 – Sessionens giltighetstid (24 timmar).

5.3 Automatiserad distribution (deploy.sh)

Genom att köra ./deploy.sh byggs både backend (WAR) och frontend (Vite), varpå ett komplett distributionsarkiv genereras: 

./deploy.sh
# Skapar distributionsarkivet: book_system.tar.gz

Arkivet innehåller allt som behövs för produktion inklusive körbara artefakter, beroenden och Systemd-konfigurationer.

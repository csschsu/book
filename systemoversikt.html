1. Systemöversikt & Syfte

Community Booking System är ett modernt webbaserat bokningssystem utformat för gemensamma lokaler, maskiner och andra anläggningsresurser. Systemet ger medlemmar och användare en snabb, visuell och intuitiv överblick över lediga och uppbokade tider i realtid, samtidigt som administratörer får full kontroll över resurser, öppettider och användarkonton.

Huvudmål med systemet:
  • Förenkla bokningsprocessen i ett guidat flöde (plats → resurs → tid → bekräftelse).
  • Skydda mot dubbelbokningar, överlappningar och felaktiga retroaktiva ändringar.
  • Erbjuda en robust, fristående och lättadministrerad driftmiljö med minimala externa beroenden.

2. Teknisk Arkitektur & Teknikstack

Systemet är byggt som en distribuerad klient-server-lösning med en Single Page Application (SPA) i frontend och ett REST-baserat Spring Boot-backend med lokal databas.

Lager / Komponent Teknik & Version Beskrivning & Roll
Frontend SPA React 18, TypeScript 5, Vite 5 Responsivt och typsäkert webbgränssnitt med komponentbaserad arkitektur.
Kalendervy React Big Calendar, Moment.js Interaktiv vecko-, dag- och månadsvy med svensk tids- och datumformatering.
Ikoner & UI-stil Lucide React, Skräddarsydd CSS Tydlig visuell feedback, modaldialoger och färgkodade statusblock.
Backend API Java 25, Spring Boot 4.1.1 (WebMVC) REST-tjänster med strikt affärslogik, validering och sessionshantering.
Autentisering Spring Security, JJWT (0.11.5), BCrypt Tillståndslösa (stateless) JWT-tokens i HTTP Authorization-headers och krypterade lösenord.
Databas & DAO SQLite 3 (via JDBC), JDBI 3 (v3.51) Filbaserad relationsdatabas med typsäkra SQL-frågor och parametriserade queries.
Drift & Tjänster Linux Systemd, Bash, OpenJDK 25 Automatisk uppstart vid boot, loggrotation via journalctl och isolerad körmiljö.

3. Datamodell & Databasstruktur

Databasen lagras i en lokal SQLite-fil (booking_system.db) och hanteras via JDBI 3. Modellen består av följande centrala entiteter:

Entitet / Tabell Nyckelfält Beskrivning & Relationer
User id, email, password, role, alias, address, code Användarkonton. Lösenord lagras saltat och hashat (BCrypt). Rollerna är BOOKUSER eller BOOKADMIN. Alias visas på bokningar i kalendern.
Location id, name, address Fysiska anläggningar, fastigheter eller områden.
Asset id, location_id, name, description Specifika resurser kopplade till en plats (t.ex. "Bana 1", "Mötesrum A").
Free id, asset_id, start_time, end_time Tillgängliga tidsblock (öppettider) då resursen är bokningsbar. Gröna block i kalendern.
Booked id, free_id, user_id, start_time, end_time Genomförda bokningar. Reserverar tid inom ett Free-block. Röda block i kalendern.

4. Funktionell Guide & Användarflöde

4.1 Bokningsprocessen (5 enkla steg)

  1. Steg 1 – Välj plats: Översiktssida där användaren väljer aktuell anläggning eller lokal.
  2. Steg 2 – Välj resurs: Val av önskad resurs bland de som finns tillgängliga på vald anläggning.
  3. Steg 3 – Välj tid i kalendern:
    • Gröna block: Lediga tider definierade av administratören.
    • Röda block: Redan bokade tider. Visar användarens alias och tidsintervall.
    • Användaren klickar på ett grönt block (eller drar ett tidsintervall i schemat) för att välja tid. Standard är 2 timmar eller blockets resterande längd.
  4. Steg 4 – Bekräfta bokning: Tidsintervallet och vald resurs sammanställs. Om användaren inte är inloggad öppnas inloggningsrutan direkt innan bokningen slutförs.
  5. Steg 5 – Klart / Kvitto: Bokningsbekräftelse visas med bokningsnummer, start- och sluttid.

4.2 Avboka / Ta bort bokning

  • För att ta bort en bokning klickar användaren direkt på sitt röda bokningsblock i kalendern.
  • Ett bekräftelsefönster öppnas med detaljer om plats, resurs, datum och tid.
  • Vid klick på "Ta bort bokning" raderas bokningen och kalendern uppdateras omedelbart.
Säkerhets- och valideringsregler:
  • Ingen ändring i dåtid: Klick på ett ledigt eller bokat block vars starttid har passerats blockeras omedelbart med felmeddelandet: "Ändring före aktuell tid är inte tillåten". Bekräftelsefönstret öppnas inte, vilket förhindrar felaktiga klick.
  • Äganderättsskydd: Endast bokningens skapare eller en användare med administratörsroll (BOOKADMIN) har behörighet att ta bort en bokning.
  • Överlappningsskydd: Två bokningar kan inte överlappa varandra eller sträcka sig utanför resursens öppettider.

5. Administratörsfunktioner (BOOKADMIN)

Användare med rollen BOOKADMIN har tillgång till administrativa flikar och verktyg i systemet:

Användaradministration (Fliken "Användare")

  • Lista samtliga registrerade användare i systemet med ID, alias, e-post, roll, telefon och skapad tid.
  • Skapa nya användare samt ange startlösenord och behörighet (BOOKUSER eller BOOKADMIN).
  • Redigera befintliga konton, uppdatera kontaktuppgifter och återställa lösenord.

Schemaläggning & Öppettider

  • Skapa och justera lediga tidsblock (Free) för respektive resurs.
  • Möjlighet till automatisk generering av öppettider över ett helt år framåt för snabb driftstart.
  • Stöd för att rensa eller redigera felaktiga öppettider.

6. Drift, Start & Underhåll

6.1 Driftsättning med Systemd

I produktionsmiljö körs backend och frontend som separata Systemd-tjänster under serviceanvändaren book: 

# Kontrollera status på backend och frontend
sudo systemctl status bookingweb
sudo systemctl status bookingapp

# Starta, stoppa eller starta om tjänsterna
sudo systemctl restart bookingweb
sudo systemctl restart bookingapp

# Visa felloggar och händelser i realtid
sudo journalctl -u bookingweb -f
sudo journalctl -u bookingapp -f

6.2 Konfiguration (application.properties)

Backend konfigureras via application.properties. Vid uppstart under Systemd läses konfigurationen in från: file:/usr/local/book/application.properties.

  • server.port=9091 – Port för REST API.
  • sqlite.db=/usr/local/book/booking_system.db – Sökväg till produktionsdatabasen.
  • jwt.secret=... – Säker nyckel för signering av JWT-tokens.
  • jwt.expiration=86400000 – Token-giltighetstid (24 timmar).

6.3 Distributionspaket & Uppdatering (deploy.sh)

Projektet innehåller ett helautomatiskt distributionsskript deploy.sh: 

./deploy.sh

Skriptet bygger backend-koden till en WAR-fil, kompilerar frontend med TypeScript och Vite, paketerar Systemd-filer och producerar ett komplett arkiv: book_system.tar.gz redo att packas upp på produktionsservern.
